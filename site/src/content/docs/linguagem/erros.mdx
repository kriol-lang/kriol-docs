O Kriol distingue duas espécies de erros de execução:

- **Bugs do programa**, como um índice fora dos limites, um resto por zero ou uma condição de `konfirma` falsa. Terminam o programa de imediato com um *panic*.
- **Falhas esperadas**, como uma entrada inválida ou um ficheiro que não existe. A função que falha **declara** que pode falhar, e quem a chama **decide** o que fazer.

## Bugs: `konfirma` e `paniku`

```kriol
konfirma(idadi >= 0, "a idade não pode ser negativa");

si estadu == 0 {
    // ...
} sinon {
    paniku(f"estado inválido: {estadu}");
}
```

Um *panic* escreve `kriol: panic at line N: mensagem` e termina o programa com o código 1. Vê [Controlo de fluxo](/linguagem/controlo-de-fluxo/).

## Falhas: o tipo `Erru`

`Erru` é um molde que já existe em todos os programas:

```kriol
molda Erru {
    textu mensage;
}
```

Uma função que pode falhar declara-o a seguir ao tipo de retorno, depois de `:`:

```kriol
fn metadi(int a, int b) num : Erru {
    si b == 0 {
        lansa Erru::{mensage: "divizon pa zero"};
    }
    divolvi a / b;
}
```

- `fn nome() int : Erru` devolve um `int` ou falha com um `Erru`.
- `fn nome() : Erru` não devolve valor, mas pode falhar.
- `lansa <erru>;` falha a função de imediato. Só pode ser usado numa função que declare `: Erru`.
- Por agora `Erru` é o único tipo de erro aceite depois de `:`.

## Tratar uma falha

Quem chama uma função que pode falhar pode tratar o erro de duas formas, descritas a seguir. Se não o tratar, **o erro não desaparece**: quando a função falhar, o programa termina nessa chamada com `kriol: panic at line N: mensagem`, tal como acontece com um índice fora dos limites. O compilador avisa disso com um *warning*, mas continua a compilar.

```kriol
fn inisiu() {
    num x = metadi(1, 0);   // warning: o erro de 'metadi' não é tratado
}                           // em execução: kriol: panic at line 2: divizon pa zero
```

Para o compilador tratar os avisos como erros, compila com `--strict`.

### `tenta`: passar o erro a quem chamou

`tenta chamada` devolve o valor da chamada, ou, se ela falhar, falha também a função atual com o mesmo erro. Por isso só pode ser usado dentro de uma função que declare `: Erru`.

```kriol
fn valida(int n) : Erru {
    si n < 0 {
        lansa Erru::{mensage: f"negativu: {n}"};
    }
}

fn kaminhu(int n) num : Erru {
    tenta valida(n);
    num m = tenta metadi(n, 4);
    divolvi m + 1;
}
```

### `sinon`: usar um valor por omissão

`chamada sinon valor` dá o valor da chamada, ou `valor` se ela falhar. O valor depois de `sinon` só é calculado quando a chamada falha, e tem de ser compatível com o tipo devolvido.

```kriol
num m = metadi(7, 0) sinon -1.0;   // -1.0
```

`sinon` tem a precedência mais baixa de todos os operadores (acima só da atribuição), por isso usa parênteses para o combinar com outros operadores: `(metadi(7, 2) sinon 0.0) == 3.5`.

## A função `inisiu`

`inisiu` também pode declarar `: Erru`. Se um erro chegar até ela sem ser tratado, o programa escreve `kriol: err: mensagem` e termina com o código 1:

```kriol
fn inisiu() : Erru {
    num x = tenta metadi(1, 0);
}
```

## Avisos e `--strict`

Ignorar o erro de uma função **declarada por ti** com `: Erru` gera o aviso `the error of 'f' is not handled, so the program stops if it fails`. É provável que seja um esquecimento, porque quem escreveu a função previu esse caminho. `toma` não gera aviso: parar quando a entrada acaba é o comportamento normal, como num índice fora dos limites, e mantém simples os primeiros programas.

```sh
kriol programa.kriol            # os avisos são mostrados, mas o programa compila
kriol --strict programa.kriol   # qualquer aviso passa a ser um erro de compilação
```

Usa `--strict` em projetos e na integração contínua para garantir que nenhum erro é ignorado.

## Regras

- Um erro não tratado termina o programa na chamada que falhou; só `tenta` e `sinon` o tratam.
- `tenta` e `sinon` só se aplicam a chamadas de funções que podem falhar.
- `tenta` só pode ser usado dentro de uma função que declare `: Erru`.
- `sinon` não se aplica a funções que não devolvem valor.
- `Erru` não pode ser redeclarado.
- O tipo de uma chamada que pode falhar não se pode escrever numa declaração: o resultado só existe para `tenta` e `sinon` o consumirem.

:::note
A função embutida `toma` também pode falhar com um `Erru`. Vê [Entrada de dados](/linguagem/entrada/).
:::
